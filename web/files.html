Nautilus, Flea, Folio

Each file manager opens a folder of 5000 empty files in its list view, and the Down key is held for 12 seconds on a virtual keyboard: the compositor passes on the one press and the file manager repeats it, about 480 files. On every machine of the lab, in Omarchy's session, under Hypoland and under stock Hyprland 0.57.1. Every cell is Hypoland / Hyprland: green where Hypoland is at least 5% better, red where it is at least 5% worse; a dash where the file manager does not run or there is nothing to count.

File managerVersionWhat it is
Nautilus51.1GNOME's file manager, GTK 4: drawn with Vulkan or OpenGL into GPU buffers, on the X200 with cairo into shared memory.
Flea0.4.1A keyboard-first file manager for Omarchy, written in Rust with GPUI (the Zed editor's UI toolkit) and drawn on the GPU through wgpu.
Folio0.1.1 (0.2.0 on aarch64)Omarchy's own file manager, written in C++ with Qt Quick.

Medians of 13 to 17 fresh sessions of each compositor per machine, alternating from 2026-11-11 17:04 to 11-12 08:59, Hypoland master r966 (after 0.3.0) against Hyprland 0.57.1-2. Folio 0.1.1 and 0.2.0 do not scroll the list to the cursor on Down (folio#18): the cursor walks off the bottom and the view stays, so for Folio the scrolling tables measure the cursor and the details pane redrawn, and do not compare with the other two. Flea opens no window on the X200 (it needs more than OpenGL 2.1) and is not installed on the Mac mini M1, Folio is not installed on the Samsung. Under Hyprland Nautilus opened no window on the X200 in that night. On the X200 Hyprland runs with Omarchy's GLES 3 override (omarchy#14764), which the file managers get too. The Mac mini 2014 had no monitor that night and ran on a headless output; the Mac mini M1's display driver reports no page flips, so it has no frames on the screen. Raw data, every session's values and the scripts.

measure.sh: how it is measured

Every number comes from a fresh session: the machine's display manager is restarted, the desktop settles for a minute, then the benchmark runs its workloads with the compositor's real clients (foot, Alacritty, Chromium, GTK 3 and 4, Qt Quick, Tk through Xwayland, Omarchy's shell). Keys and pointer motions come from a uinput device, the same path as a real keyboard. Latencies are the time from an input event to the first screen-capture frame that shows its effect. Two builds alternate through a night, so a drift of the machine hits both the same.

perf: what else is looked at

  • GPU time per frame, by the compositor's own pass profile
  • Power, by RAPL or the battery's discharge rate, net of an idle baseline
  • Memory: PSS, heap, threads and the GPU buffers the compositor holds
  • Profiles with perf and the kernel's and Mesa's symbols
  • Every machine's journal and kernel log stream to the desktop, so a machine that dies leaves its last words
